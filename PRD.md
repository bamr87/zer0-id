# Product Requirements Document (PRD): zer0-id

> A small OpenID Connect identity provider in Go with passkey (WebAuthn) login.

Open work is tracked in [GitHub Issues](https://github.com/bamr87/zer0-id/issues) and as `status: planned` entries in [features/features.yml](features/features.yml).

## 1. Overview

Single sign-on for the fleet's apps, built from the specs up: OIDC discovery, authorization code + PKCE, signed JWTs and passwordless passkeys.

| Version | Date | Notes |
| --- | --- | --- |
| 0.1 | 2026-10-28 | Initial requirements and phased roadmap (repo foundation). |

## 2. Goals

- Spec-compliant OIDC discovery, JWKS and token endpoints
- Authorization code flow with PKCE
- WebAuthn passkey registration and login

Non-goals (near term): production hosting, paid services, anything outside the roadmap below without a PRD change.

## 3. Users

- The maintainer, learning oauth 2.1 / oidc protocol details, jwt signing and key rotation by building.
- Fleet agents (hub evolution loop, backlog fan-out, `evolve` lane) that grow the repo one reviewed PR at a time.
- Fleet tie-in: SSO for the fleet console, ragio-ai, fredgar-ai and zer0-CMS; identities for fleet-mobile.

## 4. Requirements

Phases are the build order: an agent picks the earliest unserved requirement first.

### 4.1 Phase 1 — Foundation

- FR1: HTTP service exposing /healthz and /.well-known/openid-configuration
- FR2: JWKS endpoint with a generated signing key

### 4.2 Phase 2 — Core

- FR3: Authorization code + PKCE flow with a client registry
- FR4: ID token and access token issuance (RS256/EdDSA)

### 4.3 Phase 3 — Fleet integration

- FR5: WebAuthn passkey registration and login
- FR6: Conformance test run against the OpenID suite

### 4.4 Non-functional

- NFR1: CI (`.github/workflows/ci.yml`, the fleet standard gate) passes on every PR.
- NFR2: No secrets or credentials are committed; configuration comes from environment variables.
- NFR3: Autonomous lanes are off by default, open pull requests only, and never merge.
